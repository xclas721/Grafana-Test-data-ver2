# 認證與權杖說明

本文件說明前端如何處理後台/前台登入、權杖儲存、角色解析與 RBAC 顯示控制。

---

## 1. 登入入口

- 後台登入：`/login`，呼叫 `POST /api/auth/login`
- 前台登入：`/front/login`，呼叫 `POST /api/front/auth/login`

登入成功後：

- 後台 token 寫入 `authStore`
- 前台 token 寫入 `frontAuthStore`

---

## 2. 權杖儲存策略

- 預設策略：localStorage
- 後台 key：`auth_token`
- 前台 key：`front_auth_token`
- 可在初始化時切換為 sessionStorage（見 `docs/權杖儲存策略說明.md`）

---

## 3. API 帶權杖規則

- `/api/front/*`：使用前台 token
- 其餘 API：使用後台 token

由 `httpClient` 統一處理，頁面層不自行拼接 `Authorization`。

---

## 4. 角色解析（RBAC 基礎）

前端角色來源：

- JWT：解析 payload `role` claim
- Mock token：依字串前綴推斷

目前映射：

- 後台：`ADMIN` / `EDITOR` / `VIEWER`
- 前台：`MEMBER`

權限計算（後台）：

- `canEdit`：`ADMIN`、`EDITOR`
- `canDelete`：`ADMIN`

---

## 5. UI 權限控制現況

已套用頁面：

- `UserPage`
- `MemberPage`
- `SystemConfigPage`

控制內容：

- 新增按鈕
- 編輯按鈕
- 刪除按鈕
- 對應 Modal 開啟與儲存流程防呆

---

## 6. 常見風險與規範

- 風險：前端 RBAC 只能管 UI，不能替代後端授權。
- 以後端守衛/權限為最終判斷，前端僅做使用者體驗收斂。
- 角色來源以後端授權結果為準；前端 token 解析僅作畫面顯示控制。
