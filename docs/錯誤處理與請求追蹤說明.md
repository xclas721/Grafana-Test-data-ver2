# 錯誤處理與請求追蹤說明

本文件說明前端如何統一處理 API 錯誤，以及如何透過 `request id` / `correlation id` 與後端進行問題定位。

---

## 1. 錯誤分類與行為

`httpClient` 目前處理三類錯誤：

- HTTP 非 2xx：拋出 `HttpError(status, message)`
- HTTP 200 但 body `success:false`：視為業務錯誤，拋出 `HttpError`
- 請求超時：拋出 timeout error

導頁策略：

- 401：清除對應 token，導向登入頁（保留 redirect）
- 5xx：導向 `/500`

---

## 2. Result 對齊

前端 `ApiResult<T>` 對齊後端 Result，常用欄位：

- `success`
- `code`
- `message`
- `data`
- `timestamp`

頁面 catch 時，錯誤訊息呈現順序如下：

1. `message`
2. i18n 通用錯誤文案（預設訊息）

---

## 3. 請求追蹤規範

後端回應會有 `correlationId`（或 `X-Request-ID` header）。  
當遇到異常時，應回報該 ID 供後端查詢日誌。

落地方式：

- 驗證與測試流程中，遇錯於 console 記錄 `correlationId`
- 錯誤提示元件可加上「追蹤碼（correlationId）」欄位，便於支援與追蹤

---

## 4. 文件要求

錯誤處理文件應明確涵蓋：

- 說明「技術錯誤」與「業務錯誤」差異
- 讓呼叫端知道可預期的導頁行為（401/500）
- 以 `request id` / `correlation id` 作為跨系統追蹤識別
