# 介面契約同步說明

## 後端

- 啟動後提供 OpenAPI 3 規格：
  - JSON：`GET /v3/api-docs`
  - Swagger UI：`/swagger-ui.html`

## 前端產生型別（標準流程）

1. **本地**先啟動後端，執行：`npm run generate:api`
2. 產出：`src/api/generated/schema.d.ts`
3. 將 `schema.d.ts` 一併提交至版本控制，部署到 Vercel 時直接使用儲存庫內已產好的型別，無須在建置階段再拉取遠端 API。

（型別僅從本地後端產生，產出後提交版本控制即可部署。）

---

## 取得 schema.d.ts 之後要幹嘛？

產出的檔案提供**與後端 API 一致的 TypeScript 型別**，用途是：打 API 時用這些型別，讓請求/回應有型別檢查與自動完成，後端改規格後重跑 `generate:api` 就能在編譯時發現不相容。

### 用法一：在 API 層使用 schema 型別

在 `userService`、`memberService`、`apiClient` 等處，改從 schema 取型別，讓回傳值、請求 body 與後端對齊：

```ts
import type { components } from '@/api/generated/schema'

type UserVo = components['schemas']['UserVo']
type UserRequest = components['schemas']['UserRequest']
type ResultUserVo = components['schemas']['ResultUserVo']

// 打 API 時用這些型別
const result = await apiClient.get<ResultUserVo>('/api/users')
// result.data 會被推斷為 UserVo[]
```

### 用法二：讓既有 shared/types 對齊後端

若專案已有 `src/shared/types/user.ts` 等手寫型別，可以改為 re-export 自 schema，之後型別就由後端規格驅動：

```ts
// src/shared/types/user.ts
import type { components } from '@/api/generated/schema'
export type UserVo = components['schemas']['UserVo']
export type UserRequest = components['schemas']['UserRequest']
// 其餘 UI 專用型別可保留手寫
```

### 實際好處

- **型別安全**：後端改欄位或路徑後，重跑 `generate:api`，前端編譯會報錯，可立刻改對。
- **自動完成**：IDE 會依 schema 提示欄位與路徑。

### 本專案現況

- **shared/types**：`user.ts`、`member.ts`、`auth.ts` 已改為自 `@/api/generated/schema` 的 `components['schemas']` re-export（UserVo、UserRequest、MemberVo、AuthLoginRequest 等）。
- **services**：`userService`、`memberService`、`authService` 沿用上述型別；`ApiResult<T>` 仍為手寫，與後端 Result 格式對齊。
- **頁面**：UserPage、MemberPage、LoginPage、FrontLoginPage 使用 schema 型別後，對可選欄位以 `?? null` / `?? ''` 處理。

## 往後要 call API 怎麼寫？

### 1. 已有對應 service 時 → 直接用

使用者、會員、登入已有封裝好的 service，在頁面或 store 裡直接呼叫即可，型別已接 schema：

```ts
import { userService } from '@/shared/services/userService'
import { memberService } from '@/shared/services/memberService'
import { authService } from '@/shared/services/authService'

// 例：取得使用者列表
const users = await userService.getAllUsers() // UserVo[]

// 例：分頁查詢
const page = await userService.searchUsers({ page: 1, size: 10 })

// 例：登入
const result = await authService.login({ username, password }) // AuthLoginResponse
```

### 2. 要「加新 API」、但資源已有 service 時 → 在該 service 加方法

在 `userService` / `memberService` 等裡新增一個方法，用 `apiClient` + `ApiResult<型別>`，型別從 `@/shared/types` 或 schema 來：

```ts
// src/shared/services/userService.ts
import type { ApiResult, UserVo } from '@/shared/types'

// 例如後端新增 GET /api/users/export，回傳 CSV 的 blob
export const userService = {
  // ... 既有方法 ...
  exportCsv: async (): Promise<Blob> => {
    const res = await apiClient.get<Blob>(
      '/api/users/export',
      {},
      {
        Accept: 'text/csv'
      }
    )
    return res as unknown as Blob
  }
}
```

若回傳是 JSON 且落在 schema 裡，就用 `ApiResult<XXXVo>` 等：

```ts
getSomething: async (id: number): Promise<YourVo> => {
  const result = await apiClient.get<ApiResult<YourVo>>(`/api/your-path/${id}`)
  return result.data
}
```

### 3. 全新資源（例如 SystemConfig、自訂模組）→ 開新 service + 用 schema 型別

1. 後端有對應 API 時，先跑一次 `npm run generate:api`，讓 `schema.d.ts` 裡有該 API 的型別。
2. 在 `shared/types` 若要統一入口，可加一個 `xxx.ts` re-export schema 的型別（例如 `SystemConfigVo`）。
3. 新增 `src/shared/services/xxxService.ts`，用 `apiClient.get/post/put/delete` + `ApiResult<型別>` 打 API，型別用 `@/shared/types` 或 `import type { components } from '@/api/generated/schema'`。

```ts
// 例：src/shared/services/systemConfigService.ts
import { apiClient } from './apiClient'
import type { ApiResult } from '@/shared/types'
import type { components } from '@/api/generated/schema'

type SystemConfigVo = components['schemas']['SystemConfigVo']
type SystemConfigRequest = components['schemas']['SystemConfigRequest']

export const systemConfigService = {
  getAll: async (): Promise<SystemConfigVo[]> => {
    const result = await apiClient.get<ApiResult<SystemConfigVo[]>>('/api/system-configs')
    return result.data ?? []
  },
  create: async (body: SystemConfigRequest): Promise<SystemConfigVo> => {
    const result = await apiClient.post<ApiResult<SystemConfigVo>>('/api/system-configs', body)
    return result.data
  }
}
```

### 4. 在頁面 / 元件裡呼叫

- 盡量用 service 層（不要在各頁直接 `apiClient.get`），方便複用與測試。
- 回傳型別已是 schema 對齊的 Vo/Dto，欄位可能為可選（`id?`），使用處用 `?? null`、`?? ''` 或可選鏈 `?.` 即可。
