# 文件維護規範

本文件整理「前端文件怎樣才算可長期維護」，並說明本專案採用的落地方式。

---

## 1. 本專案文件目標

- 讓新成員可在短時間定位資訊（架構、授權、部署、契約）
- 讓變更可追蹤（文件與程式碼在同一儲存庫同步調整）
- 降低知識集中在口頭傳承

---

## 2. 文件整理原則

本專案文件採以下原則：

- **單一真實來源**：契約與型別以 OpenAPI 產物為準
- **文件即程式碼**：文件皆為 Markdown，與程式一起版控
- **任務導向**：每份文件回答一種問題（怎麼部署、怎麼認證、怎麼追錯）
- **可執行範例**：保留可直接執行的指令與流程
- **低耦合索引**：README 提供入口，細節放 `docs/`

---

## 3. 維護規範

- 新增 API：同步更新 `docs/介面契約同步說明.md`
- 新增登入/授權規則：同步更新 `docs/認證與權杖說明.md`
- 調整 request/error 行為：同步更新 `docs/錯誤處理與請求追蹤說明.md`
- 調整環境變數：同步更新 `docs/設定治理說明.md` 與 README
- 重大架構調整：同步更新 `docs/架構與請求流程.md`

---

## 4. 完成定義（文件面）

每次重要改動至少檢查：

1. README 索引連結是否可點
2. docs 是否有對應主題文件
3. 指令與環境變數是否仍可執行
4. 是否仍有過時文件尚未清理
